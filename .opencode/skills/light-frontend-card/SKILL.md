# 轻前端角色卡编写技能

## 核心设计哲学

轻前端卡的本质：**模型只输出标记符，正则脚本将标记符替换为预设计的HTML/CSS**。

这与"重前端"（Canvas粒子、画面震动、JS动画）的根本区别在于：
- 轻前端：CSS 视觉装饰 + HTML 结构化面板。模型输出的仍然是纯文本标记，渲染交给正则。
- 重前端：JS 运行时特效。需要注入并执行 JavaScript，复杂度高，容易出错。

## 三层架构

```
模型输出层（标记符）
    ↓
正则脚本层（匹配 → 替换）
    ↓
渲染层（HTML + CSS）
```

### 层1：模型输出层

角色在世界书条目中被告知在回复末尾输出特定标记符：

```
<status_panel>
<time>晴; 2025年3月27日 14:30</time>
<scene>宫益坂女子学园 走廊</scene>
<character>Ichika; Honami</character>
...
</status_panel>
```

关键原则：
- 标记符必须简洁、不干扰模型正常回复
- 使用XML风格标签（`<tag>...</tag>`）或中文标记（`【标记名】`）
- 标签内的换行和缩进保持一致格式

### 层2：正则脚本层

正则脚本配置在角色卡的 `extensions.regex_scripts` 中：

```json
{
  "scriptName": "状态栏",
  "findRegex": "<status_panel>([\\s\\S]*?)<\\/status_panel>",
  "replaceString": "完整的HTML替换内容...",
  "placement": [1, 2],
  "disabled": false,
  "markdownOnly": false,
  "promptOnly": false
}
```

正则脚本的执行时机由 `placement` 控制：
- `[1, 2]` = 角色回复 + 用户发送前都执行
- `[1]` = 仅在角色回复时执行
- `[2]` = 仅在用户输入发送前执行

`replaceString` 是完整的 HTML 代码。核心技巧：
- 在替换内容中使用 `$1`, `$2` 引用捕获组
- 把 HTML 放在 markdown 代码块中（` ```html ... ``` `），ST 会渲染它
- 替换内容可以非常大（pjsk 的状态栏替换内容达 170KB）

### 层3：渲染层

HTML 代码块内的内容会被 ST 渲染为实际的 UI 元素。CSS 写在 `<style>` 标签内，可以：
- 使用 CSS 变量 `:root { --custom-color: ... }` 方便主题切换
- 引用外部 CDN 资源（Font Awesome 图标等）
- 使用 CSS Grid / Flexbox 做响应式布局
- 使用 CSS 过渡和动画（仅限 CSS，不写 JS）

## 标记符系统设计

### 标记符分类

| 类型 | 格式 | 用途 | 示例 |
|------|------|------|------|
| 状态面板 | `<status_panel>...</status_panel>` | 回合制状态面板 | 时间、地点、好感度、内心想法 |
| 开场页面 | `【开场白】` | 首条消息的开场动画 | 世界观介绍、角色选择 |
| 功能页面 | `【团队建立】` 等 | 用户交互页面 | 创建乐队、选择剧情线 |
| 文字装饰 | `(xxのyy)` → `<span>xxのyy</span>` | 内联文字样式 | 日文助词美化、关键词高亮 |
| 错误修复 | `<message>无</message>` → 空 | 格式修正 | 清理模型产生的多余标签 |

### 标记符设计原则

1. **简洁性**：标记符长度不超过 30 字符，模型容易记住
2. **唯一性**：避免与自然对话文本冲突
3. **可解析性**：正则能精确匹配，不会误伤正常文本
4. **顺序性**：标记符之间有明确的先后顺序约束

## 世界书组织原则

### 层级结构

一个质量高的轻前端卡遵循严格的层级结构：

```
世界观（1条）
  └─ 子世界观/场景（5-10条）
      └─ 角色（每角色1条）
          └─ 角色关系/称谓（每团体1条）
      └─ 场景细节（每场景1条）
          └─ 住宅/房间（每角色1条）
      └─ 剧情事件（每事件1条）
      └─ NPC（每NPC 1条）
```

### 命名规范

- 使用 Emoji 前缀标记分组：`🦋25时` `☘️MMJ` `🎸VBS`
- 方括号标记类型：`【场景】` `【npc】` `【混活】`
- 分隔线划定区块：`—————混活—————`
- 角色命名包含团队缩写：`【🦋25时】朝比奈真冬`

### 条目内容规范

角色条目：统一格式（外貌、性格、背景、能力、关系）
场景条目：从视觉细节出发（色调、光影、布局、氛围）
事件条目：起因→经过→关键节点→结局结构

## 工作流程

### 创建新轻前端卡

1. **规划标记符系统**
   - 确定需要哪些面板（状态栏、开场页等）
   - 设计标记符名称和格式
   - 编写世界书条目告知模型如何输出标记符

2. **编写正则脚本**
   - 一个标记符对应一条正则脚本
   - 替换内容为完整 HTML + CSS
   - 测试正则是否会误匹配

3. **组织世界书**
   - 按层级搭建条目（世界观 → 场景 → 角色 → 事件）
   - 为每个条目编写精确的触发键
   - 检查条目间是否有冗余覆盖

4. **视觉效果与排版**
   - CSS 变量统一主题色
   - 响应式布局适配手机和桌面
   - 使用半透明背景和毛玻璃效果保持 ST 原生风格

5. **OCR 验证**
   - 在 ST 中实际运行，截图
   - OCR 检查渲染内容是否与预期一致
   - 验证标记符不会被误触发

### 升级现有卡为轻前端卡

1. 检查已有正则脚本和标记符
2. 识别缺少的面板类型
3. 重构世界书条目命名和层级
4. 逐一添加新的正则脚本
5. OCR 验证

## 禁止事项

- 禁止在替换内容中使用 `<script>` 标签（ST 安全策略可能拦截）
- 禁止使用 Canvas / WebGL
- 禁止使用会阻塞渲染的长动画
- 禁止在模型回复中直接输出 HTML（应使用标记符 + 正则替换）
- 禁止使用 `position: fixed` 覆盖 ST 原生 UI
- 禁止使用外部不可控资源（可能失效的图片链接）

## 性能考量

- 单个替换内容不超过 200KB（pjsk 状态栏 170KB 为上限参考）
- 正则脚本总数建议不超过 10 条
- CSS 动画使用 `transform` 和 `opacity`（GPU 加速），避免 `width/height` 动画
- 避免深层嵌套的 CSS 选择器

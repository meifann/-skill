# 标记符系统设计参考

## 标记符的分类与设计模式

### A类：状态面板标记符

用于回合制输出角色状态信息。模型每轮回复末尾输出。

```
首标记: <status_panel>
子标记:
  <time>天气描述; 日期 时间</time>
  <scene>15字地点描述</scene>
  <character>在场角色（分号分隔）</character>
  <affection>角色1:数值; 角色2:数值</affection>
  <thoughts>角色内心想法（换行分隔）</thoughts>
  <message>信息流/通知</message>
  <story>当前剧情线</story>
尾标记: </status_panel>
```

世界书条目中需要明确告知模型每个子标签的格式要求（见 `格式强调` 条目示例）。

### B类：功能页面标记符

用于呈现配置表单、团队管理等交互页面。在特定时机输出一次。

```
【开场白】      → 首条消息，渲染为欢迎配置页
【团队建立】    → 用户触发，渲染为乐队创建页
【剧情选择】    → 剧情节点，渲染为分支选择页
```

功能页面标记符通常不含子标签，正则脚本直接替换为完整 HTML。

### C类：装饰标记符

用于内联文字美化，不产生页面级替换。

```
(团队名)の      → 美化日文助词
**关键词**      → 加粗高亮
```

### D类：修正标记符

用于清理模型产生的格式错误。

```
<message>无</message>  → 删除
<empty></empty>        → 删除
```

## 标记符在世界书中的位置

标记符规范应放在世界书的**基础规则区域**，位于世界观条目之后、角色条目之前：

```
[00] 世界观
[01] 格式强调 ← 状态栏标记符规范放这里
[02] 虚拟歌姬命名规范 ← 装饰标记符规范放这里
[03] 对白格式
[04] 好感度系统
...
```

## 格式强调 条目标准模板

```markdown
[系统协议：状态面板生成规范]
每次角色回复正文结束后，输出 <status_panel> 包裹的状态区块。

1. 标签功能定义
- <time>：当前时间，格式：天气; 日期 时间
- <scene>：当前地点，15字内
- <character>：在场角色，分号+空格分隔
- <affection>：好感度数值总览，格式"罗马音:数值"，分号分隔
- <thoughts>：角色内心想法，格式"罗马音：想法"，换行分隔
- <message>：信息流/通知内容
- <story>：当前剧情线

2. 强制格式示例
<status_panel>
<time>晴; 2025年3月27日 14:30</time>
<scene>宫益坂女子学园 走廊</scene>
<character>Ichika; Honami</character>
<affection>Ichika:45; Honami:62</affection>
<thoughts>
Ichika：今天穗波看起来很开心呢
</thoughts>
<message>无</message>
<story>混活：奔跑吧！体育祭！; 第一话：筹备开始</story>
</status_panel>

3. 输出约束
- 不得省略任何标签（即使内容为空也写出标签对）
- 标签顺序严格按示例
- <affection> 必须列出所有已知角色的当前值
```

## 标记符命名原则

1. **与自然语言区分**：使用尖括号或【】包裹，避免裸关键词
2. **长度控制**：标记名不超过 20 字符
3. **语义清晰**：标记名能直接反映其用途
4. **层级明确**：父子标签的语义关系清晰（如 `<status_panel><time>`）

## 正则脚本与标记符的对应关系

每个标记符对应一条正则脚本。脚本的顺序不影响执行，但建议按优先级排列：

1. 修正类脚本（先清除错误标签）
2. 装饰类脚本（内联样式）
3. 面板类脚本（完整替换）

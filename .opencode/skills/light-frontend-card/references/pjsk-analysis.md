## 关键设计模式

### 1. Emoji + 方括号的层级标记

```
【🦋25时】朝比奈真冬        ← 角色条目
【🦋25时_V】初音未来        ← 虚拟歌手在25时SEKAI中的形象
【场景】宫益坂女子学园      ← 场景条目
【npn】青龙院樱子            ← NPC条目
【混活】奔跑吧！体育祭！    ← 活动剧情条目
【ick一箱】叩响未来！！      ← 角色专属箱活
```

### 2. 分隔线组织剧情

```
—————混活—————            ← 空内容，纯分隔
  [143-153] 混合活动
—————L/n箱活—————
  [155-159] L/n专属活动
—————25时箱活—————
  [161-164] 25时专属活动
```

分隔线条目 content 为空，纯视觉标记。不需要触发键。

### 3. 习惯称谓规范化

每个团队有独立的称谓条目，规定成员间的称呼方式。触发键包含成员名和团队缩写。

### 4. 虚拟歌手的多重身份

同一虚拟歌手（如初音未来）在5个SEKAI中有5套不同的形象、性格、身份。条目用 `_V` 后缀区分。

### 5. 场景的视觉优先描述

每个场景条目从视觉细节出发：
```
<神山公园>
地面与设施：地面是平整的沙土地...
围栏与告示牌：整个公园被绿色的金属铁丝网围起来...
环境与背景：远处能看到...
```

## 正则脚本配合世界书的设计

### 状态栏脚本 + 格式强调条目的协作

世界书条目 `[58] 格式强调` 规定了模型的输出格式：

```
[系统协议：状态面板生成规范]
每次角色回复正文结束后，输出 <status_panel> 包裹的状态区块。
```

模型按规范输出标记符，正则脚本 `状态栏` 将 `<status_panel>...</status_panel>` 替换为 170KB 的 HTML 面板。模型不需要知道 HTML 的实现细节。

### 开场白脚本的设计

模型在 `first_mes` 中输出：
```
【开场白】
【团队建立】
<status_panel>...</status_panel>
```

三条正则脚本分别匹配这三个标记符，将它们替换为对应的 HTML 面板。首条消息呈现为精美的配置表单。

## 为什么 pjsk 能包含 318 条目而不乱

1. **严格层级**：世界 → SEKAI → 团队 → 角色 → 房间，逐级细化
2. **命名规范**：Emoji前缀+角色名，编译器般的精确
3. **分隔线**：大区块间用空内容分隔线划分
4. **称谓独立**：每个团体的称谓规则是独立条目
5. **触发键精确**：每个条目的触发键都经过精心设计，不会误触发
6. **禁用不用的**：第一学年剧情线（三周年前）全部禁用，保持世界书干净
